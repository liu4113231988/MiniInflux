# InfluxDB 3 对齐路线图（2026-08）

基于 InfluxDB 3 Core（3.11）功能集的差距分析。定位：保持单机、InfluxQL 兼容、AOT 友好，不做 SQL 全量引擎 / Python 处理引擎 / Parquet 对象存储架构。

## P0 — v2 写入 API 兼容（已完成 2026-08-27）

- [x] `POST /api/v2/write?bucket=&org=&precision=` — `Program.cs:272` / `V2WriteSupport.cs:10`
  - [x] `bucket` → db 映射；`bucket` 为 `db/rp` 形式时拆出 rp（`V2WriteSupport.TryResolveBucket`，修 whitespace trim）
  - [x] `org` 参数接受并忽略（endpoint 签名 `string? org`，`_ = org`）
  - [x] gzip 解压、请求体上限（复用 `WritePointsAsync` + `ReadRequestBodyBytesAsync`：Content-Encoding gzip 探测、解压后上限 `MaxRequestBodyBytes`，gzip bomb 防护）
  - [x] 错误码/错误体对齐 v2 风格（v2 分支返回 `V2ErrorResponse {"code","message"}`：`invalid` 400 / `too large` 413 / `too many requests` 429 / `unavailable` 503；`AppJsonContext.V2ErrorResponse`）
  - [x] 接受 `Authorization: Token xxx`（v2 客户端默认）与既有 Basic 认证（`AuthenticationGuard.cs:77` Token 分支 + `TokenMatches` 对 `password` 与 `username:password` 双形式校验，`ExtractCredentials` 识别 `Token`/`Bearer`；`Bearer` 先行满足 P2 Token 校验部分）

## P1 — Last Value Cache（已完成 2026-08-27）

- [x] 每 series 最新点缓存：写路径顺带更新，flush 后从 segment footer maxTime 校验/回填 — `Storage/LastValueCache.cs:12` / `Storage/TsdbEngine.cs:69,2834,2397,2525`
  - 写路径 `AddWrittenPoints`/`AddBufferedPoints` 增量 `Update`（同 timestamp LWW 合并字段，乱序不覆盖）；`Recover` 回放同步回填
  - `FlushLocked`/`FlushSnapshotAsync` 快照后 `ValidateLastValueCacheFromFooter` 以段 footer `MaxTime` 对齐并回填缺失（`TsdbEngine.cs:3010`）
  - 删除/过期失效：`DropDatabase`→`ClearDb`、`DropMeasurement`→`RemoveMeasurement`、`DropSeries`→`RemoveSeriesBatch`、`DeleteBuffered`→按 `measurement` 维度清除、`CleanupExpiredShards`→全清并懒回填
- [x] `last()` / “当前值”查询走缓存，目标 <10ms — `Query/QueryExecutor.cs:2628,2646,2713`
  - `TryServeFromLastValueCache` 拦截 `last()`（含 `GROUP BY host/*`）与 `SELECT * … ORDER BY time DESC LIMIT 1`，字典命中 <10ms（预热后实测 ~1ms），`Report.UsedLastValueCache`
  - miss 时 `BackfillLastValueCacheEntry` 经 `TryReadSeriesDescending limit 1` 按 `seriesFilter` 回填；`Min/MaxTime` 越界或缺字段/被 tombstone 则回退全扫描保证正确性
  - 实测：`LastValueCacheTests` 6/6 通过，`WritePath_UpdatesCache_AndLastQuery_HitsCache_Under10Ms` 二次命中 <10ms；全量 323/323

## P2 — Token 认证体系（已完成 2026-08-27）

- [x] Bearer token 校验（与 Basic 并存）— `AuthenticationGuard.cs:31,152` / `Program.cs:682`
  - `ExtractCredentials` 同时识别 `Basic` / `Token` / `Bearer`（三者在 `Authorization` 头并存，`query` 参数 `u/p` 仅当 `AllowQueryCredentials` 时），`Evaluate` 按 `CredentialSource` 分流，`TokenMatches` 优先查 `TokenStore` 等权 token 再回退超管 `Password`/`Username:Password`，与 Basic 共用限流窗口与 `Retry-After`
- [x] 多命名 token：创建 / 列出 / 吊销（先做等权 token，后续再考虑 db 级权限）— `Storage/TokenStore.cs:12` / `Program.cs:636` / `AppJsonContext.cs:47`
  - 持久化 `data/meta/tokens.json`（`TokenJsonContext`，AOT 友好，原子 tmp→move），`SHA256(raw) base64` 落盘，`Prefix=raw[..8]` 列表脱敏；`Create(name)` 校验 `^[A-Za-z0-9_-]{1,64}$` 且唯一，`mini_<base64url(32)>` 随机，`Validate` 定时比较，多线程 `lock`；`List`/`Revoke(id)`；`AuthenticationGuard.SetTokenStore` 注入，`POST/GET /admin/api/tokens`、`DELETE /admin/api/tokens/{id}`（均 `EnsureAuthorized`，创建返回 `201` 含一次性明文 `token`，列表仅 `id/name/prefix/createdAtNs`，吊销返回 `200`），实测 `TokenStoreTests` 3/3 通过，全量 326/326

## P2 — v3 查询端点（已完成 2026-08-27）

- [x] `POST /api/v3/query_influxql`：JSON 请求体 `{db, q, params?, format?, epoch?}`，复用现有执行器 — `Program.cs:371`
  - `db`/`q` 必填（缺失返回 400 + `{"error":"missing required parameter db|q"}`），同时接受 query string / form / JSON body 三种来源与 `database`/`query` 别名
  - `format` 仅支持 `json`（默认），其他值返回 `unsupported format: ... (supported: json)`；`epoch` 复用 v1 的除数换算
  - 响应为 v1 风格 `{"results":[...]}` 信封；执行错误（非超时/取消）以 400 + `{"error"}` 返回，超时/取消保持既有状态码语义
  - 纳入 gzip 响应压缩路径（`ResponseCompressionSupport`），并顺带修复压缩中间件此前只设 `Content-Encoding` 头、未真正包装响应体的缺陷（现经 `GZipStream` 包装并在 dispose 时刷 trailer）

## P3 — 参数化查询（已完成 2026-08-27）

- [x] v1/v3 查询端点支持绑定参数，防注入并复用解析缓存 — `Protocol/QueryParamBinder.cs:12` / `Protocol/InfluxQlParser.cs:30` / `Query/QueryExecutor.cs`
  - WHERE 谓词中的 `$name` 占位符在解析期提取为 `ParamFilter`（tag/field/time/regex 各操作符），字符串字面量内的 `$` 不受影响
  - `ApplyParams` 在解析树级别绑定：值永不拼回 SQL 文本，无注入面；缺参抛 `missing parameter: $name`，类型与操作符不匹配抛 FormatException；时间参数支持 RFC3339 字符串与数值，并与字面量时间范围取交集
  - 模板经 `ParseCached` 跨请求复用（上限 1024 条、无 LRU 的有界缓存，AOT 友好）；绑定产生新列表，不修改缓存模板
  - `/query?params={"host":"a"}`（GET query/form）与 v3 `params`（JSON body/query）两条入口统一接入；`ExecuteWithReport`/`ExecuteChunkedWithReport`/raw JSON 快路径均先绑定后执行；OR 谓词、非 SELECT 语句中的占位符直接拒绝
  - 实测：`P3ParameterizedQueryTests` 29/29 通过（占位符解析、类型绑定、防注入、模板复用、chunked 路径），全量 355/355；HTTP 冒烟 17/17（gzip 解压、v3 校验、缺参 400）

## 明确不对齐

- SQL 全量查询引擎（DataFusion 等价物）
- Processing Engine（Python VM 插件）
- Parquet / 对象存储无盘架构
- Flight SQL gRPC、Enterprise HA
