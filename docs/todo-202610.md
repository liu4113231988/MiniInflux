## P0 — 数据安全、权限与静默错误结果

### P0-1 查询加速路径丢失无法下推的谓词

- [x] 修复 `BuildSeriesFilter` 对无法解析谓词的静默跳过
- 状态：任一滴谓词无法解析时返回 `null`，LVC/聚合下推/降序 raw/streaming group-by 快路径统一回退逐点匹配。
- 验证：`Query_WithTagKeyThatIsAlsoStringField_DoesNotDropPredicate` 覆盖 buffer、flush 后、`last`、`mean`、raw 与 OR 组合。
- 证据：`MiniInflux.Engine/Query/QueryExecutor.cs:1938-1952` 对 `matches == null` 直接 `continue`；`GetMatchingSeries` 在 string field 或数值歧义时返回 `null`（`QueryExecutor.cs:1962-1966`）。
- 受影响路径：
  - Last Value Cache：`QueryExecutor.cs:1017-1031`、`2659`、`2748-2772`，只拒绝 OR，不重新应用 tag/field 谓词。
  - 聚合下推：`QueryExecutor.cs:1033-1037`、`3274-3303`，只拒绝 `FieldFilters`（`3289`），不拒绝无法下推的 tag 谓词。
  - 降序 raw 快路径：`QueryExecutor.cs:1087-1089`、`1253-1261`，当 `seriesFilter != null` 时把 `tagFiltersApplied` 置真（`1096`/`1109`），后续不再逐点过滤。
- 影响：`WHERE` 中混有 string field 谓词时，聚合、`last()`、降序 raw 会返回全 measurement 或超集数据；结果不报错。
- 修复方向：任一滴谓词无法解析时禁用 LVC/下推/降序快路径，退回逐点 `MatchesTagFilters` 路径；或为快路径传入完整谓词并在输出前再次校验。不要用“忽略该谓词”换取速度。
- 验收：buffer/已 flush/LVC 冷热四种状态各覆盖 `SELECT mean/last/raw ... WHERE stringField='x'`、`tag='x' AND stringField='y'`、含 OR 的组合；结果必须与全扫描基准一致。

### P0-2 WAL 撕裂尾部不截断，重启后的新写入可能再次丢失

- [x] WAL 启动时定位最后一条有效记录并截断，或在损坏尾部后强制新建 WAL 文件
- 状态：`WalManager` 构造时扫描所有 `.wal`，按记录长度 + CRC 定位最后有效字节并 `SetLength`；同时钳制越过有效尾部的 checkpoint。
- 验证：`Wal_WithTornTail_IsTruncatedBeforeAppendAndReplayStillReturnsValidRecords` 覆盖二次写入/二次重启；`Wal_WithCrcCorruptionInLastRecord_TruncatesItBeforeAppending` 覆盖 CRC 撕裂。
- 证据：`MiniInflux.Engine/Storage/Wal.cs:68-94` 以 `FileMode.Append` 打开最大编号文件，`_currentFileSize = Length`；`Wal.cs:445-494` 回放遇到短记录/CRC 失败直接 `break`，仓库内没有任何 `SetLength`。
- 故障链：崩溃留下撕裂记录 → 重启后新写入追加到撕裂字节之后 → 第二次崩溃 → 回放仍停在原撕裂点，第一次重启后已 ACK 的写入全部被跳过；若期间发生 checkpoint/rotation 才可能绕过。
- 影响：已返回 HTTP 2xx 的写入在“二次崩溃且未 flush”场景下永久丢失，且无错误提示。
- 修复方向：打开 WAL 时扫描到最后一条完整记录，`SetLength(lastValidOffset)` 后再以 Append 打开；或检测到损坏尾部时立即轮转到新文件并记录告警。
- 验收：新增“写入 → 撕裂最后一条记录 → 重启 → 再写入 → 再次重启”的确定性测试，断言第二次重启后两组数据都在；同时覆盖 CRC 错误和长度截断两种撕裂。

### P0-3 WAL checkpoint 可越过在途、已 ACK 的写入

- [x] 为 WAL 追加、buffer 发布和 checkpoint 建立单调水位
- 状态：写路径在 `AppendBatch` → `AddWrittenPoints` → `UpdateBufferReplayFloor` 期间持有 `_walAppendGate` 读锁；`UpdateWalCheckpoint` 持写锁快照，避免 checkpoint 越过尚未发布 floor 的记录。
- 验证：`WalCheckpoint_WaitsForAppendPublication_AndStopsAtEarliestUnflushedReplayFloor` 强制 checkpoint 与 append/publish gate 竞争，验证 checkpoint 等待 gate 释放，并精确等于两个 RP 中最早的未 flush floor。
- 剩余验证：尚未精确注入“实际 append 后、buffer floor 发布前暂停”并模拟崩溃/重启；该端到端故障测试仍待补充。
- 证据：写路径先 `AppendBatch`（`TsdbEngine.cs:278`），再 `AddWrittenPoints`（`282`），最后才 `UpdateBufferReplayFloor`（`284`）；`UpdateBufferReplayFloor` 只为已有 buffer 的 key 建条目（`3078-3084`）。`UpdateWalCheckpoint` 在快照为空时直接 checkpoint 到 `_wal.CurrentPosition`（`3098-3105`），且与写路径没有共同锁。
- 故障链：某新 `db|rp` 的 WAL 已追加但尚未发布 floor，另一个 key 的 flush 看到空快照并 checkpoint 到该记录之后；此时崩溃，记录既不在段中也不会被回放。
- 影响：小概率但可复现的已确认写入丢失，属于 durability 缺陷。
- 修复方向：维护“已 ACK 且已发布 buffer floor 的最高 WAL 位置”单调水位；checkpoint 只能推进到该水位。或者让 append→floor 发布持有同一把锁，checkpoint 读取同一把锁下的水位。
- 验收：并发写不同 RP + 反复 flush/checkpoint，注入“append 后暂停、checkpoint、崩溃”的测试；恢复后所有已 ACK 点可查。

## P1 — 查询语义不完整或与文档不一致

### P1-1 GROUP BY 把非聚合项和 DISTINCT 静默变成 `count`

- [x] `SELECT value ... GROUP BY host` 不再返回 count；非聚合 + time group 明确报错或实现 raw 分组
- 证据：分组分支在函数分支之前执行（`QueryExecutor.cs:1140-1162`）；`AggGroupBy` 只保留 `Func != ""` 的项，没有则伪造 `count(*)`（`1564-1565`，并行路径 `1632-1633` 相同）。DISTINCT 项的 `Func` 为空，因此也被吞掉。
- 已复现：`SELECT value FROM probe GROUP BY host` 返回列 `count`。
- 修复方向：按 InfluxDB 语义校验 SELECT 项与 GROUP BY 的组合；支持 raw GROUP BY tag 时走 raw 分组路径，否则返回明确错误。`SELECT DISTINCT a, DISTINCT b` 也不应因 `SingleOrDefault` 抛异常（`QueryExecutor.cs:1185-1189`）。
- 验收：raw group、`value, mean(other)` 混合、DISTINCT + time group、多 DISTINCT 均有明确结果/错误。

### P1-2 `count(DISTINCT field)` 在分组路径丢失 distinct 语义

- [x] 分组聚合统一传递 `IsCountDistinct`
- 证据：`BuildGroupedRows` 非行展开分支调用 `Calc(..., it.UnitNs)`，没有传 `it.IsCountDistinct`（`QueryExecutor.cs:1842-1852`）；行展开分支（`1868`）和非分组路径（`2941`）都传了。`Calc` 仅在 `isCountDistinct` 为真时去重（`3051`）。
- 已复现：3 行中 2 个不同值，返回 3。
- 验收：`count(distinct)` 在 grouped/ungrouped/row-expanding 三种路径结果一致。

### P1-3 分组查询中的序列/数学函数被压缩成单值，`elapsed` 为 null

- [ ] 行展开函数在 GROUP BY 路径保持逐点序列
- 证据：无行展开函数时每 group 只生成一行（`QueryExecutor.cs:1842-1852`），`Calc` 对 `difference` 返回首尾差、`cumulative_sum` 返回总和、`moving_average` 返回平均、数学函数只取 `nums[^1]`（`3071-3088`）。`elapsed` 只在 `BuildFunctionSeries` 中实现（`3038-3039`），`Calc` 没有对应分支，落到 `_ => null`（`3089`）。
- 已复现：`SELECT elapsed(value) ... GROUP BY host` 每行 null。
- 修复方向：把 `difference/derivative/moving_average/cumulative_sum/elapsed/数学函数` 视为行展开；或在带 GROUP BY 时明确拒绝未实现组合。`elapsed` 的单位参数也要生效。
- 验收：分组与不分组结果逐点一致；`elapsed` 不再返回 null。

### P1-4 fill、SLIMIT/SOFFSET、AS、count(*)、SELECT INTO 的已知边角

- [x] `fill(zero)` 与 `fill (0)` 解析；`fill(previous)` 遇到空值不重置
- [x] raw SELECT 使用显式 AS 别名
- [x] 所有返回路径应用 SLIMIT/SOFFSET
- [x] `count(*)` 语义统一
- [x] `SELECT INTO` 使用目标库默认 RP，并返回写入统计而不是源行

证据与现象：

- `InfluxQlParser.cs:602-604` 只识别字面量 `"0"`，`fill(zero)` 落到 `None`；只匹配 `" FILL("`，`fill (0)` 不生效。`ApplyFill` 在已有桶值为 null 时用 null 覆盖 `prevValues`（`QueryExecutor.cs:2544-2556`），破坏 `fill(previous)` 的跨空桶延续。
- raw 输出列使用 `SelectItem.Field`（`QueryExecutor.cs:1193-1204`、`3963-3966`），聚合路径才用 `Alias`；`SELECT value AS v` 不生效（已复现）。
- raw grouped 快路径（`1387-1405`）和 time-only 聚合（`1745-1782`）直接 return，未调用 `ApplySeriesWindow`；SLIMIT/SOFFSET 被忽略。
- `count(*)` 在下推路径展开为每 field 一列（`3291-3298`），流式/函数路径返回单列（`1470`、`2916-2920`），与其它聚合混用时 `IsCountStar` 只接受单项（`3596-3597`），可能得到 0。
- `ParseIntoTarget` 对一段/两段目标硬编码 `"autogen"`（`2023-2032`），不使用 `GetDefaultRpName`；`Select` 写回后返回源 rows（`1239-1246`、`2006-2014`），不是 InfluxDB 的 `written` 结果。

验收：以上每种组合都有对照 InfluxDB 1.8 的行为测试或明确的“不支持”错误。

### P1-11 `DROP SHARD`/`DROP RETENTION POLICY` 不完整

- [x] DROP SHARD 清理 buffer、LVC、series/tag index，并与 flush/compaction 串行化

- 状态：DROP SHARD/RP 获取写入目录排他锁，暂停并等待 compaction，先 flush/checkpoint 已接受的写入，再在 segment publication gate 下删除目录和更新 catalog。目录删除失败显式抛错，不再静默移除 manifest。TombstoneStore 仅清除指定 RP 的标记并保留 legacy 全 RP 标记；manifest 持久化单调 shard ID 高水位，删除 RP 后重启不复用已删除 shard ID。

### P1-13 compaction 失败清理与 tombstone 退役竞态
